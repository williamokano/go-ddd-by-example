Discuss

3.4 testcontainers: a real Postgres per test package

Goal
A reusable helper that starts Postgres, applies the embedded migrations and returns a *pgxpool.Pool.
Concepts
Level 3: adapter integration tests
Creates
internal/platform/postgres/pool.go, internal/platform/postgres/pgtest/pgtest.go (build tag integration), the Makefile target test-integration
TDD script
  1. An integration test: migrations go up, then down, then up again without error (this catches broken Down sections early).
  2. pgtest.New(t) returns a pool where SELECT 1 works. The container is shared across the package via TestMain.
Pitfall

Starting a container per test turns a 2-second suite into 2 minutes. Use one per package and isolate tests with random IDs.

3.5 The Postgres VenueRepository

Goal
Pass the same contract suite as the fake.
Creates
internal/venue/adapters/driven/postgres/venue_repository.go, mapping.go, venue_repository_test.go
TDD script
  1. Wire venuerepotest.Run(t, newPostgresRepo). Everything is red. Good.
  2. Make "Get unknown → ErrVenueNotFound" pass (map pgx.ErrNoRows).
  3. Make "Save new then Get" pass: one transaction that inserts the venue and its sections. Map rows → domain.RehydrateVenue.
  4. Make "Save existing" pass: UpdateVenue, then replace the sections (delete + insert, which is fine because layouts only change in Draft).
  5. Make "stale version → ErrConcurrentModification" pass: UpdateVenue affected 0 rows.
  6. Make "Save drains events" pass. For now the events are drained and dropped. Part 5 writes them to the outbox.
Why this proves the architecture

Count the lines you changed in domain and application in this lesson. It should be zero. If you had to change them, something leaked, and we discuss what.

3.6 Optimistic concurrency under real contention

Goal
See the version check work when two goroutines race.
Concepts
ADR-011
TDD script
  1. Two goroutines load the same draft venue and each add a different section, then both save. Exactly one gets ErrConcurrentModification, and the stored venue has exactly one of the sections.
  2. Add a RetryOnConflict(ctx, attempts, fn) helper to the application layer and use it in AddSectionHandler. Test it with the fake repo by injecting a conflict once.
Discuss

Why is retrying the whole load → decide → save cycle safe, but retrying only the save wrong?
